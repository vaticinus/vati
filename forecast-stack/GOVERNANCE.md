# Governance

Toni Zemani is the initial maintainer. This is maintainer-led open source, not a foundation or a promise of community ownership of Vaticinus the company.

## Decisions

Discuss changes to public APIs, scoring rules, model defaults and source admission in an issue before implementation. Record the problem, alternatives, compatibility cost and evaluation plan. Maintainers make and explain the decision in public. Urgent security fixes may be discussed privately until disclosure is safe.

A benchmark win does not bypass code review. A maintainer's hypothesis gets the same leakage, cost and holdout checks as any contribution. Publish negative results; never remove an unfavorable valid result to improve the scoreboard.

## Contributor path

- **Contributor:** an accepted, attributed contribution of code, evaluation, source verification, docs or design.
- **Component steward:** nominated after sustained reviewed work in a bounded component. The nomination names scope, evidence of judgment, review responsibilities and conflicts of interest. Maintainer approval is explicit and recorded; no automatic permissions based on PR count.
- **Maintainer:** nominated by an existing maintainer after a public discussion of review quality and project responsibility. Security access and release permissions are granted separately and least-privilege.

Stewards help set their component roadmap and review work. Inactivity or repeated breaches of review/security obligations can lead to scoped access removal with an explanation and a route to appeal to another maintainer where one is available.

## What contributors receive

MIT reuse rights, retained copyright, named release attribution, reproducible tools without a hosted subscription, and a visible route to technical responsibility. Accepted negative results and reproducibility work count as substantive contributions.

No token, equity, revenue share, employment, bounty payment or free compute is promised. A funded program must be announced separately with budget, eligibility and payment terms. Never ask contributors to run paid calls on the assumption of reimbursement.

The public repo is the source of truth for its released components. Private product needs do not silently change public scoring rules or withdraw already granted MIT rights. Forking remains an option when priorities diverge.
